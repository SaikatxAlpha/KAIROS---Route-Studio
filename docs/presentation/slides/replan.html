Dynamic replanning

When something happens, the problem is rebuilt and re-solved

Five synthetic events

  • Traffic delay in an area
  • Vehicle breakdown
  • Urgent order with a tight window
  • Service-time shock in an area
  • Adverse weather everywhere

What the engine does

  • Observes each van’s realised progress at the event
  • Builds a residual VRP: pseudo-depots at committed stops
  • Compares hold-and-insert, re-optimise, KAIROS replan
  • Diffs the plans and scores them on the same scenarios

Real algorithms on synthetic events: every replan is a PyVRP solve, not an animation

Each active vehicle becomes its own vehicle type in PyVRP, starting where it will be free and when. Idle vans can be dispatched at a cost. A broken van’s stops become orphans to reassign; an urgent order on an Amazon instance gets its travel times from the calibrated model. The UI shows which stops moved between vehicles and why.
